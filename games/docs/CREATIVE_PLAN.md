## 0. 写死的约束（任何创意先过这五关）

1. **零第三方依赖**（含测试框架）；MSBuild `-m:1`、无 NuGet 网络。
2. **公开 API 只增不改**——动 `NekoClicker.Core` 公开表面 = minor + 重生成 `PublicApi.txt`；不动 = patch 或不升版。
3. **存档格式不动**（`SaveSerializer.CurrentVersion` 仍为 `1`）。要加存档状态的必须先过 D5，标 ⚠️。
4. **引擎/内容分离**：优先"内容包自己能做"（`IGameModule` / `Counters` / `Modifier` 有先例）。
5. **主线长度不变（本版新增，硬约束）**——任何候选都**不许**让"从第一层走到结局"变长。判据（全部满足才算过）：
   - **不加门槛**：不往任何 `EraDefinition.Completion` / 结局条件 / 解锁链上添新的必做项；
   - **不加必答**：不新增会拦结局的待答表态（1.6.0 起"答不完拿不到结局"，多一条表态 = 主线变长）；
   - **不占主循环**：入口可选、可无视，不往点击/购买的主循环里塞新的必看弹窗；
   - **不稀释密度**：同屏信息量与作答节奏不因它变慢（纸条那种"收起就走"的形态才是合格线）。
   - 例外只有一种：**全新内容包自带的主线**（A4）——它自己定义自己的长度，不碰既有 11 包的主线。
   - **这条是守卫，不是散文**——`engine/tests/EraStageTests.cs` 加 `MainLineLengthTests`，横扫 `TestGame.AllContentPacks()`（派生式，新包自动进网，照 `AllEraPacks` 的先例），四条断言：
     1. **冻结长度**：每包的 `{纪元数, 最大 Index, 每个 EraDefinition.Completion.Describe() 指纹}` 必须与**用例内写死的期望表**逐字相同 ⇒ **加纪元 / 抬门槛 / 换指标 = 红**。期望表不入本文档——真相只留一份，免得文档与用例各说各话。
     2. **不加必答**：`ChoiceDefinition` **没有**"是否拦结局"字段（已核实）——拦结局的机制在 `EndingDefinition.Condition`，所以此条 = 冻结 `{EndingDefinition.Id, Priority, Condition.Describe()}` 指纹，与第 1 条同表同判。表态目前**只能**经 `IGameMetrics.StanceWeight(string)` 进条件树（`NumericMetric` 里没有表态指标），新增任何引用表态的条件叶子即红，且需同步过第 1 条。
     3. **三个盯死点**：`capsule_*` / `second_life_*` / `stages_walked_total` 不得出现在任何条件树里；树源 = 建筑/升级/成就的 `Unlock` + `EraDefinition.Completion` + `EndingDefinition.Condition`（四类消费者全覆盖）。`NumericMetric` 里**没有**阶段数与徽章指标，所以这条只能是条件树扫描，**不能**写成指标白名单。末尾 `Check.AtLeast(纪元总数, 40, …)` 防空扫。
     4. **堵后门**：`CustomCondition` 的谓词不可指纹（`Describe` 只是作者自己写的 `Description`），是唯一能绕过第 1 条悄悄加门槛的叶子——所以完成条件/结局条件里**不许**出现 `CustomCondition`。现状是内容里零使用（守卫首跑即绿）。
   - 现状基线（本版实测）：11 包中 9 包有纪元、共 **49 个**（九命 9、实验室 7、公司 3、其余各 5；`Neko`/`Cafe` 零纪元）；`Stages` 目前只有公司用。**白名单守卫（`GameContentBuilder.MonotonicMetrics` / `ForbiddenInCompletion`）只管"指标会不会下降"，不管"门槛有没有被抬高"——上面第 1 条补的正是它漏的那半。**

**前置**：1.12.1 仍未打包发布（RELEASING ⑨⑩⑪ 未走）；创意默认排在发布动作之后，除非明确并行。

## 档 A — 零引擎改动（每条已过第五关审计）

### A1 — 结局纪念卡（"这一局的墓志铭"）· 代价 S · 推荐首做

结局落定时把这一局摘要拼成可复制纯文本。数据全在快照里（`EndingView`/`EraView`/`AchievementCount`/`PlayTimeSeconds`/`CodexView`），纯宿主排版。

- **主线影响：零**——它只在**结局已落定后**出现（主线之外），不加任何门槛、不发任何弹窗。
- **拆步骤**：① 终端 `games/hosts/Demo.Cli/RecapCard.cs` 纯函数 `Build(GameSnapshot)` + 结算帧按键（键位避开 E/I；动帮助帧先过 `FrameRenderTests` 宽高不变量）；② `app.js` 同构纯函数 `recapText(state)` + 结局 sheet（约 `app.js:652`）加「复制这一局」（复用 sheet 形态，按钮在滚动区外）；③ 测试：`RecapCardTests`（跨宿主逐字一致、无结局不画、无纪元省层行、K/M/B/T 行与 `FormatShort` 一致）+ `web-smoke` 4 条（按钮存在、只发复制、文本框只读、首句截断不抛）；④ 不升版。
- **风险**：两端断句规则必须写死（按 `。！？` 首个句末标点）；帧宽不变量。

### A6 — 跨包彩蛋（结局互指）· 代价 S · 与 A1 同波

11 包结局文本各埋一句下一个包的"门牌"。环形草案定死：`cafe → ninelives → lab → company → apocalypse → library → god → civ → cyber → dream → neko → cafe`。

- **主线影响：零**——改的是结局文本（主**线终点之后**的读物），不加条件、不动散文预算表之外的机制。每句 ≤40 字，`ProseToneTests` 档位同步，单独可回滚提交。
- **注意**：只加"门牌"句，不动原句结构；`ninelines/ninelives` id 分裂未决，环里的 id 以最终拍板为准。

### A2 — 种子挑战（"同一只猫"）· 代价 M

`?challenge=<正整数种子>` 开内存局（照抄跳层令牌先例：`GameHost.cs:550`，`autosave="disabled"`、完事即弃），双方同种子各跑各的，用 A1 的纪念卡比分数——不做排行榜。

- **主线影响：零（结构保证）**——挑战局**不落盘**，与玩家正常进度物理隔离；不设倒计时、不设必做目标（时长是双方口头约定），不往正常局里加任何东西。
- **拆步骤**：① Web 会话接 seed（seed 目前只在终端：`CliOptions.cs:130`）；② URL 组合矩阵（`challenge=0` 拒绝；与 `?share=` 互斥，"一次只开一扇门"先例）；③ 页面一行提示；④ `api-test` 3 条（种子 = 链接种子、autosave disabled、互斥拒绝）+ `web-smoke` 2 条；⑤ 不升版（宿主-only）。
- **依赖**：站在 A1 的纪念卡上（比分数要有卡可比）。

### A3 — 时光胶囊纸条 · 代价 M · ⚠️ 动存档

带到期时间的纸条，到期后**下次读档**才进 1.11.0 那条待读队列——离线收益的镜像。

- **主线影响：零**——纸条是纯叙事彩蛋，不进任何完成条件/解锁链；"到期"用读档时扫描（不在线轮询，不占 tick）。
- **数据草案**：`SaveData` 加 `capsules` 表（`{id, text, dueAtUtc}`）；`CurrentVersion` 1→2 + v1→v2 迁移（= D5 的第一次真演练）；上限 ≤500 字 / 在册 ≤3 张 / 拒绝写过去的时间。
- **拆步骤**：0. 👤 先拍 D5；1. 迁移 + 表 + `LeaveCapsule`（minor，重生成快照）；2. 到期扫描进读档路径，UI 零新形态；3. 测试：迁移用例、到期未到不出/到出一次/答过不重复、UTC 假时钟两例；4. minor + 存档迁移。
- **风险**：**第五关盯死点**——将来若有人想拿"胶囊到期"当解锁门，直接违反主线不变量；由 §0 第五关守卫第 3 条兜住（`capsule_*` 不得进任何条件树），此处不再另写用例。

### A5 — 生涯时间线面板（Web）· 代价 S~M · minor

- **与 GUI 轮的衔接**：`3fb9d46` 已把六台重建器改成键复用/指纹——新卡片**从第一天就按这套规矩写**（不逐帧重建），别再欠 W21 式的债。

### A4 — 第 12 个内容包：一条没被用满的轴 · 代价 M~L

### B2 — 阶段奖励口径（D10、D9）

- **主线影响：零（加一条硬约束）**——阶段是**派生显示**（1.9.0 的设计原意），徽章计数器**永不进任何 `Completion`/解锁条件**（§0 守卫第 3 条）；"每层 ≈2 次舍命"的减层若做，必须以"主线变短"为验收（这正是用户这条约束要的方向），而不是变长。
