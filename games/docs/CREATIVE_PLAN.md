## 0. 写死的约束（任何创意先过这四关）

1. **零第三方依赖**（含测试框架）；MSBuild `-m:1`、无 NuGet 网络。
2. **公开 API 只增不改**——动 `NekoClicker.Core` 公开表面 = minor + 重生成 `engine/core/PublicApi.txt` 快照；不动 = patch 或不升版。
3. **存档格式不动**（`SaveSerializer.CurrentVersion` 仍为 `1`）。要加存档状态的创意必须先过 D5（迁移演练），标 ⚠️。
4. **引擎/内容分离**：优先"内容包自己能做"（`IGameModule` / `Counters` / `Modifier` 有先例：幸福感、士气、被阅读度全在核心零改动下落地）。

**前置**：工作树 `1.12.0` 未打 tag、未发布（D18 未决）。创意默认排在 1.12.0 结掉之后，除非明确并行。

**三条全局注意**（每个创意都会碰到）：

- **文档计数会漂移**：`api-test.ps1` 源码里那句"当前 112 处调用点"、`web-smoke` 注释里的"271 条断言"、README/STATUS 的用例数——`TestCountDriftTests` 会点名，加检查点/断言时必须同步注释。
- **跨宿主逐字一致有先例可抄**：K/M/B/T 那轮把"两个宿主说同一句话"做成了跨套件守卫（`web-smoke` §29 从 `NumbersTests` 读期望值）。A1/A2 的"同一份文本两边一样"照这条路走。
- **会话隔离有现成模式**：跳层令牌会话已经演示过"只在内存、关掉自动存档"（`GameHost.cs:550`、`Program.cs:523/629` 的 `autosave="disabled"`）。A2 的挑战会话照抄，不发明新机制。

## 档 A — 零引擎改动，可直接做

### A1 — 结局纪念卡（"这一局的墓志铭"）· 代价 S · 推荐首做

结局落定时，把这一局的摘要拼成一段**可复制的纯文本**。数据**全部已在快照里**：`EndingView`（Id/Name/Icon/Text，`Views.cs:519`）、`EraView`、`AchievementCount`、`PlayTimeSeconds`、`CodexView`、历史累计——纯宿主排版。

**文本格式草案**（行序写死，两端逐字一致）：

```
── 这一局的墓志铭 ──────────────
🌌 结局：〈Name〉（〈Icon〉）
层：〈当前层名〉（第 k/n 层）          ← 无纪元包省略此行
成就：37/66 ｜ 叙事图鉴：38/40
用时：5h 23m ｜ 历史累计：1.16E18（K/M/B/T 那套 FormatShort）
“〈结局 Text 的第一句〉……”           ← 只摘第一句，不整段抄
── NekoClicker 1.12.0 ────────────
```

**拆步骤**：

1. **终端**：新小文件 `games/hosts/Demo.Cli/RecapCard.cs`——纯函数 `Build(GameSnapshot)`；结算帧加键（键位候选 `R`；**E/I 已被导出/导入占用**，`CliOptions.cs` 帮助文本同步）。帧内加提示行要过 `FrameRenderTests` 的宽高不变量（`EveryFrameFitsTheViewportExactly` / `HelpOverlayFitsTheViewportExactly`——帮助层加一行就是改一处断言，先看它再动）。
2. **Web**：`app.js` 加同构纯函数 `recapText(state)`（注释写明"与终端逐字一致"）；结局 sheet（`state.ending` 常驻入口，约 `app.js:652`）加「复制这一局」按钮 + 只读文本框——复用存档窗口那套 sheet 形态（`.sheet-body` 豁免照抄：按钮在滚动区外）。
3. **测试**：
   - `engine/tests/RecapCardTests`（tests 工程已同时引用两个宿主，`SaveTransferHostTests` 是先例）：① 同一快照两端字符串逐字相同；② 无结局（`Ending == null`）返回空、不画；③ 无纪元包省略层行；④ K/M/B/T 那行与 `NumFormat.FormatShort` 一致（从 `NumbersTests` 读期望值的先例照抄）。
   - `web-smoke`：按钮存在、点了只发复制命令、文本框只读、结局 Text 第一句截断不抛——照 §24 存档窗口那批写法。
   - 可选 `api-test` 1 条（结局态才出按钮）——检查点 112 → 113 要同步注释。
4. **版本位**：不升版（Core 一行没动），随下一 patch 结桶或单独结。

**风险**：帮助层/帧宽不变量（上文已列）；`Ending.Text` 第一句的断句规则要写死（按 `。！？` 第一个句末标点，含省略号处理），否则两端断句不一致直接红在逐字对拍上。

### A2 — 种子挑战（"同一只猫"）· 代价 M

固定 seed + 固定时长跑一局，结算分用 A1 的纪念卡比对（成就数 + 图鉴数）。挑战参数编进 URL：`?challenge=<正整数种子>`，沿用 `?package=` 的宿主参数解析习惯。

**拆步骤**：

0. **已核对**：seed 只在终端接线（`CliOptions.cs:130` → `GameSession.cs:136`），Web 无 seed 口；种子确定性有守卫（`SimulationTests.SameSeed_ProducesIdenticalRuns`）。
1. **会话隔离照抄跳层先例**：挑战会话 = 内存局、`autosave="disabled"`（`GameHost.cs:550` 已演示这条路）——**不写 `saves/X.json`，不碰真人进度**，完事即弃。
2. URL 组合矩阵（要在 `Program.cs` 的参数解析处定死）：
   | 组合 | 行为 |
   |---|---|
   | `?challenge=N` | 内存局、种子 N、页面顶部提示"挑战：种子 N" |
   | `?challenge=N&package=X` | 在包 X 上开挑战 |
   | `?challenge=0` | 拒绝（挑战必须可复现；终端 0=随机的语义**不带进来**），一句人话 |
   | `?challenge=N&share=…` | 拒绝（挑战与分享互斥，同 `?k=` 与 `epoch` 那条"一次只开一扇门"） |
3. 页面一行提示 + 结束时展示 A1 纪念卡——**A2 站在 A1 肩上**，顺序在后。
4. **测试**：`api-test` 打 `?challenge=`：断言会话种子 = 链接种子（快照同轨迹两连打）、`autosave=disabled`、`?challenge=0` 与 `&share=` 组合的拒绝文案；`web-smoke` 提示行 2 条。
5. **版本位**：不升版（宿主-only，Core 不动）。

**注意**：默认挑战时长**不做成引擎概念**——它是"双方口头约定跑 10 分钟再看卡"，页面只提示、不倒计时（G5 的"前 10 分钟 ≤3 条叙事"已是社区基准）。想做倒计时就把它挂到 D7（通知角标）一起拍。

### A3 — 时光胶囊纸条 · 代价 M · ⚠️ 动存档

用 `LoreChannel.Note`（1.11.0 的纸条队列）做"写给未来的自己"：留一张带到期时间的纸条，到期后**下次读档**才进待读队列。机制上是离线收益的镜像。

**数据与 API 草案**（先定形，实现等 D5）：

- 存档：`SaveData` 加一张 `capsules` 表（`{ id, text, dueAtUtc(UTC ticks), }`）；**`CurrentVersion` 1 → 2** + 一条 `ISaveMigration` v1→v2（老存档 = 空表）。
- 时间口径：**存 UTC**（`IClock` 注入可测；时区/夏令时不进存档）；到期判定只发生在**读档时**（`ApplyLoad` 后扫一遍到期项 → 进 `PendingLorePopups`），在线不轮询（省一个 tick 钩子）。
- 公开入口草案：`LeaveCapsule(string text, DateTime dueUtc)` / `GameSnapshot` 只增一个"在册胶囊数"（可选）——**minor**。
- 滥用上限（构建期/运行期都卡）：正文 ≤500 字、同时在册 ≤3 张、到期时间必须 > now（拒绝写过去）。

**拆步骤**：

0. 👤 **先拍 D5**：要不要借这条线做第一次真存档迁移演练（机器有：`ISaveMigration` + `SaveTests.Migration_UpgradesLegacySaves`；生产零迁移史）。拍"不借"则本条一直挂着。
1. 迁移 + 表结构 + `LeaveCapsule`（minor，重生成 `PublicApi.txt`）。
2. 到期扫描进 `SaveManager` 读档路径；纸条 UI **零新形态**——到期后就是 1.11.0 那张"纸"。
3. **测试**：迁移用例（v1 存档读入 → 空表不崩）；到期未到不出 / 到出一次 / 答过不重复出（队列幂等用例照抄 `LoreTests.NoteChannel_*`）；UTC 跨时区两例（`IClock` 假时钟）。
4. **版本位**：minor + 存档迁移（全仓第一次，D5 演练产物一并归档）。

### A4 — 第 12 个内容包：一条没被用满的轴 · 代价 M~L

现有 11 个包把 Era/Lore/Choice/Stage/第二资源都用过了，但 `IGameModule` 注释里点名的那类"引擎不认识的系统"（**随 tick 生长、可干预、可错过**）还没有包做过。三个候选概念卡（世界观等 👤 定，机制先备好）：

| 候选 | 模块状态 | 错过机制 | 货币轴 | 叙事钩子 |
|---|---|---|---|---|
| **值班表**（猫咖排班） | 每格班次的在岗猫娘表 | 错过的班次 = 流失的幸福 | 幸福（复用 #1 先例） | "她今天没来上班" |
| **节目编排**（电台） | 节目单（时段 × 节目） | 烂节目播出去收不回来 | 收听率（计数器） | "凌晨三点那档没人听" |
| **花园**（`IGameModule` 注释点名） | 植株生长阶段（tick 推进） | 不浇水就枯萎（单调性要小心：**别进完成条件**） | 收获物（计数器） | "种子是上一任留下的" |

**拆步骤**（照 `PACK_01_CAT_CAFE.md` / `PACK_README.md` 既有立项顺序）：

0. 👤 定概念（三选一或另提），进 `SETTING.md`；定层叙事（5 层哪五段）。
1. 数值曲线沿用已验证配方（`Apocalypse/Buildings.cs:7`：相邻价格 ×6.7~16.5、产量 ×5.4~10、第 3 座起价格倍率 > 产量倍率）。
2. 模块先行（`Configure` 补定义 / `OnTick` 推进 / `OnOffline` 补离线——**离线补算是硬要求**，`IGameModule.OnOffline` 注释点名的坑：不处理就凭空落后一大截）。
3. **完成条件只用单调指标**（R3 铁律）：花园枯萎、班次流失这类"会掉的"量**一律不进完成条件**（`MonotonicGuard` 会拦，先想清楚再铺内容）。
4. 结构测试 → 机器人走到结局 → G5 前 10 分钟 ≤3 条 → `ProseToneTests` 新档 → "拥有 ⇒ 已解锁"横扫。
5. **分期**：先 1 层可玩 MVP（建筑/升级/叙事各一档）验模块手感，再铺满 5 层——避免 11 包那种"铺完才发现节奏不对"。
6. **版本位**：不升版（Core 不动）。

### A6 — 跨包彩蛋（结局互指）· 代价 S

11 个包的结局文本里各埋一处下一个包的"门牌"。纯叙事改动，零机制。

**环形草案**（顺序 = 包 id 环，谁指谁先定死，改文只改句子不改环）：

```
cafe → ninelives → lab → company → apocalypse → library
     → god → civ → cyber → dream → neko → cafe（回到起点）
```

**拆步骤**：

1. 每包结局 1 句、**≤40 字**（`endings.text`——§12.4.1 界线：叙事散文，K/M/B/T 那条线不碰；`ProseToneTests` 的散文预算表会拒绝超档）。

4. **版本位**：不升版。

**风险**：结局 Text 是玩家高频看到的文本，改它 = 改已有玩家的观感——句子里只加"门牌"（一句互指），不动原句结构；1.12.0 未发布，现在改还来得及并进它或单独 patch。

### B3 — 数字口径统一（D14）· 最接近机械，拍一句就能做
