## 1. 一句话结论

**这一轮把"能玩"变成了"一条命令能玩"，真人玩了一局，交了 4 条样本。**

- 行格式：`S <utc> <包id> <表态id> <选项id> <模拟秒> <真实秒> <宽限期参数> <会话内第几条>`
  （`games/hosts/Shared/ChoiceLatencyLog.cs:102`）。复跑：
  `Select-String -Path artifacts\latency.txt -Pattern '^S\t' -Encoding UTF8`。

### 2.2 新增 `tools/play-web.ps1`（这台机器上唯一能把宿主开起来的路径）

三个环境原因叠在一起，缺一条都起不来（详表见 §3）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\play-web.ps1 -Package company
# -Port <端口> / -SaveRoot <目录>（隔离实验局）/ -Stop（只停这个端口）/ -StopAll（收工清场）
```

- 脚本开发中**自己踩了两个坑，都当场修掉并写进注释**：① 第一版按**进程名**杀宿主，
  于是起第二个实例会把第一个一起杀掉（实测：给人玩的 5273 被实验用的 5274 带走）；
  现在**只认端口**。② `-Port` 此前只用于打印与探活、**没传给宿主**，
  第二个实例红在 `address already in use`；现在传 `--urls`。
- **埋点按端口隔离**：5273 仍是 `artifacts/latency.txt`（真人那条线一个字节不动），
  其它端口落 `artifacts/play-<端口>/`。

### 2.3 H2 的服务端那一半：三种互斥现象排掉两种

## 3. 这一台机器上会咬人的三条（本轮新查清，写进 `STATUS` §7）

| # | 现象 | 根因 | 对策 |
|---|---|---|---|
| 1 | `You must install .NET to run this application` | 只有 `Microsoft.AspNetCore.App 10.0.x`，而宿主声明 `net8.0` | `DOTNET_ROLL_FORWARD=Major` |
| 2 | 起来了又**立刻退出**，栈顶是 `Microsoft.Extensions.Logging` | EventLog provider 写 Windows 事件日志被拒 → 日志器自己抛异常 → 进程退出；**真正的原因被次生异常盖住**（本轮真凶只是一句无害的 `WebRootPath was not found`） | `Logging__EventLog__LogLevel__Default=None` |
| 3 | `/api/*` 全通、**首页 404** | 开发期 `bin` 旁边没有 `wwwroot`，内容根默认是工作目录 | `ASPNETCORE_CONTENTROOT=<games/hosts/Web>` |

另外两条**操作上的**坑（都踩实了）：

- **活宿主会锁 `bin` 里的 dll** ⇒ 构建红在 `MSB3027 / MSB3021`（`locked by: neko-clicker-web`）。
  构建前先 `play-web.ps1 -StopAll`。
- **别把启动器的输出接管道** ⇒ 分离启动的宿主继承了调用方的 stdout 句柄，读不到 EOF，
  命令永不返回（`tools/start.ps1` 顶部早有这条）；`job_kill` 收掉那个作业时还会**连带收走宿主**。

## 5. 怎么自己复跑一遍（判据，不是"应该"）

```powershell
# 0) 收工清场（活宿主会锁 bin）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\play-web.ps1 -StopAll

# 1) 重建（改了 C# 就必须做；只改 wwwroot 可以跳过）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dnet.ps1 build games/hosts/Web/NekoClicker.Web.csproj -c Debug

# 2) 起这一局（同一条命令给真人玩）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\play-web.ps1 -Package company
#    浏览器： http://127.0.0.1:5273/?package=company     ← ⚠ 参数不能省，省了就是末世包

# 3) 真人样本的判据
Select-String -Path artifacts\latency.txt -Pattern '^S\t' -Encoding UTF8

# 4) 换快照之前必须先重建测试项目，否则 public-api.ps1 会打印**上一个版本**的公开表面
powershell -NoProfile -ExecutionPolicy Bypass -File tools\dnet.ps1 build engine\tests\NekoClicker.Core.Tests.csproj -c Debug
powershell -NoProfile -ExecutionPolicy Bypass -File tools\public-api.ps1

# 5) 三条验收命令（数会变，以它们自己打印的那一行为准）
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build.ps1 -Strict
powershell -NoProfile -ExecutionPolicy Bypass -File tools\api-test.ps1
node tools\web-smoke.mjs
```

## 6. 验收实测（这一轮在**这棵树上**跑出来的三个数）

| 命令 | 结果 | 备注 |
|---|---|---|
| `tools\build.ps1 -Strict` | **599 个用例全部通过**，退出码 0 | 含公开 API 快照守卫与 `VersionTests`（版本号三处一致 + CHANGELOG 有当前版本条目） |
| `tools\api-test.ps1` | **105 / 105**（源码 105 处 ｜ 执行 105 ｜ 通过 105 ｜ 失败 0 ｜ 跳过 0），退出码 0 | 它自己挑空闲端口起宿主；`/api/ping` 报 **`apiVersion=1.12.1` / `assemblyVersion=1.12.1.0`** —— 这条同时是"版本号真的进了产物"的端到端证据 |
| `node tools\web-smoke.mjs` | **271 / 271**，退出码 0 | 无头 DOM 桩；**布局与配色仍不在它射程内**（H3 那类待办照旧） |

基线出处：`OPEN_WORK` §0.32.5 记的是 599 / 105 / 271（W17 那一轮），本轮**三个数都没变**
——因为这一轮一行用例、一行前端代码都没加。

**没有被这三条命令覆盖、但本轮亲眼核过的**：

- `artifacts/latency.txt` 的 4 条 `S` 行在跑完全部套件之后**逐字还在**（`api-test` 用的是自己的临时
  存档根与自己的端口，不碰真人那份数据）；
- `engine/core/PublicApi.txt` 重生成之后与 HEAD 的 `--numstat` = **`1 1`**、行数 **2032**
  —— 这是"公开 API 一行没动"的证据，也是 `1.12.1` 该记成 patch 的依据。
