# 页面级检查：为什么必须有，以及那条漏网的 bug

> 这份文档记的是一次**真实事故**和一个**结构性缺口**。
> 结论先写：**HTTP 层全绿 ≠ 页面能用。** 这个仓库目前没有任何检查会打开页面看一眼，
> 而 1.5.0 因此把一个"整页冻结"的 bug 推上了 `main`。

---

## 一、事故：`lastFrameAt`（1.5.0 引入，`b48f2fa` 修复）

浏览器控制台只有一行：

```
app.js:86  Uncaught ReferenceError: lastFrameAt is not defined
    at source.onmessage (app.js:86:17)
```

`app.js` 的 SSE 帧处理函数里，给一个**从未声明**的标识符赋值。ES module 是**严格模式**，
所以这在运行时抛 `ReferenceError`——而它在**每一帧的第一行**，于是：

```
recomputeAffordable();   // 从未执行
render();                // 从未执行
```

**整页不更新**：大数字、进度条、建筑、升级、图鉴、成就、日志、离线弹窗——**全都不动**。
页面在初次加载后看起来"能用"，所以很容易被误当成"某个小地方没生效"。

**修法**：补 `let lastFrameAt = 0;`。它全文**只写不读**（原本大概想做节流或"新鲜度"指示，
那个功能从没写完），注释里如实标明，免得后人以为它存在。

## 二、为什么四种检查全都没拦住

| 检查 | 它实际证明什么 | 为什么漏掉这个 bug |
|---|---|---|
| `tools/api-test.ps1`（**55/55 全绿**） | HTTP 协议、序列化、端点、静态文件可达 | 它**不执行页面里的 JS**。协议全对，页面照样可以是死的 |
| `tools/build.ps1 -Strict` | C# 编译与引擎行为 | 前端 JS **不在编译范围内**——这个 bug 发生时**一条前端断言都不存在**（无头冒烟套件是这份记录写完 17 分钟后才补上的，见 §三；今天它由 `node tools/web-smoke.mjs` 跑） |
| `node --check app.js` | **语法**成立 | "给未声明变量赋值"在模块里是**运行时报错**，不是语法错误，静态检查抓不到 |
| 人工读代码 | 取决于读的人 | 该 subagent **主动报告过**"Web 侧判据没在真浏览器里目视过"——它诚实标了未验证，**而那个未验证的地方恰好就是坏的** |

**这不是"某个人不小心"，是"这条路根本没有检查"。**

## 三、应有的检查：把页面真的跑起来

首选的形态（不依赖任何第三方库、不需要真浏览器）：

**headless DOM 桩件烟测** —— 用一个最小 `document` / `EventSource` / `location` / `performance`
替身**加载 `app.js`**，喂一份**合成的快照**（含待答表态、含 delta 帧），驱动 `render()`，
断言：

1. **没有异常抛出**（这一条就能抓住 `lastFrameAt` 这类错误）；
2. 关键的类状态正确（例如有待答表态时窗口该出现、答完该消失）。

Node 在本机可用，因此这条路可行，且符合仓库"零第三方依赖"的底线。

若桩件某处确实做不了，**必须在报告里明说做不到**，并退化为"逐个标识符核对其声明处"的
系统性静态扫描——**但那远不如真跑一次**，两者不是同一等级的保证。

## 四、往后该守的规矩

- **任何 `wwwroot/*` 的改动**，交付时必须附**页面真跑过**的证据；只有"文件内容正确 /
  服务器返回的是新文件 / 括号平衡"**不算**——这三条我全验过，页面仍然是死的。
- **不许拿 `node --check` 当唯一证据**：它只证语法。
- **"未在真浏览器里目视过"必须在报告里显式写出**（这一条上一位做得对），
  但不能就此当作可以发布——**要么补一个 headless 烟测，要么明确说这条没验**。

## 五、记录在案的教训（元层面）

这次定位靠的是**用户贴出的那一行控制台输出**，而在此之前的三次判断**全是错的**：

1. 猜"浏览器缓存"（服务器确实没发 `Cache-Control`，但这不是原因）；
2. 猜"CSS 特异性"（`.hidden` 带 `!important`，压根不是原因）；
3. 猜"文件被别人换掉了"（我把 `$r.Content.Length` 即**字符数**当成了字节数，
   39084 B 与 32077 字符对不上就下了结论）。

三次都是**没把事实看清就先下结论**。同一轮里我还**按端口找到 PID 却没按 PID 查进程名**，
把 `SGTool` 与 `QQ` 误指为"别的游戏实例"，并**第三次**把中文写进 shell 字符串字面量导致
整条命令 `ParserError` 未执行。

**可复用的规则**：页面不对劲时，**先要控制台红字，再动任何猜测**。
一行真实的报错胜过三轮推理。
