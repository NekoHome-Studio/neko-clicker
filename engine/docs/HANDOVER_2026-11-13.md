## 2. 这一轮做了什么

### 2.1 C1《猫娘电台》：第一个"点击是干扰"的包（创意池档 C 首条）

`engine/content/Radio/`（12 个文件）：9 建筑 / 36 升级 / 61 成就 / 8 增益 / 10 条"听众来电" / 40 图鉴 / 2 结局 / 2 纪元。

- **核心反转、引擎零改动**：`BroadcastModule` 在 `OnAttach` 订阅既有 `ClickedEvent`——每点一次收听率掉 0.5%；
  `ClickBasePower=0.1`、`ClickCpsRatio=0.001` 把点击收益压到极小。乱点亏本，最优策略是"堆播音建筑、管住手"。
- **收听率**（`listenership`）：闭式解照图书馆被阅读度范式，均衡 L\* = 240 × 播音类建筑数；
  产量乘数走 `Scaling(CustomCounter)`：没人听 ×0.5（不归零死锁）、2 万 ×1.0、6 万 ×2.0 封顶。
- **R3 纪律**：会掉的收听率不进纪元完成条件（只用累计赚取 1B）；结局等末层主线完成后判定，
  「被听到最后」额外要求停播时收听率 ≥60K，兜底「无人再听」只依赖主线。
- **对"1 层 MVP"的结构性偏离**：转生结算要求 `Era < MaxEraIndex`——一层包永远舍不了命、执照恒 0、
  永久线结构性买不起。故做**两层**（band_1 → band_2）；转生除数按本包 1e9 阶梯标定 1e3。已记入 CREATIVE_PLAN。
- **双向无头实测（反转被实锤）**：
  - 盲点机器人（balance-lab，种子 42）：3h01m 通关 2/2 层、图鉴 40/40，拿**兜底结局**——收听率被它点掉了；
  - 管住手机器人（`RadioContentTests`，开局 bootstrap 后不再点）：拿**好结局**，终局收听率 **63289 > 60000**。
  - 注意与图书馆守卫的差异：被阅读度不被点击掉、收听率会——**好结局必须用不点击的机器人验证**。
  - 第一版"全程不点击"机器人无法开局（没点击收入买不起第一座建筑）空转超时；改成"开局点几下、堆起来就管住手"。

### 2.3 D3 新包脚手架：`tools/new-pack.ps1`（创意池档 D）

```powershell
pwsh -File tools/new-pack.ps1 -Id garden -Name "猫娘花园" -Currency "花"   # 生成
pwsh -File tools/new-pack.ps1 -Id garden -Name "猫娘花园" -Currency "花" -Remove   # 回滚
```

- 一条命令生成 **两层 vanilla MVP**（11 文件：C#×9 + text.json + csproj），**自动注册 6 处、自动更新 7 张冻结表**；
  `-Remove` 干净互逆。曲线直接复用 C1 的合规配方（相邻价格 ×5~20、产量 ×3~12、第 3 座起价格比>产量比）。
- **只生成内容、不加测试方法**——跨包守卫经 `AllContentPacks` 自动覆盖新包，用例数恒 619。
- **踩掉的三个坑**（都写进了工具注释）：
  1. ContentText 十表 eras/endings 同值 2、stances/choices 同值 0，"Radio 行后插"会**跨表串插** →
     改"按表名定位表块、块内插一行"；
  2. 主线基线回滚原靠"复算指纹精确匹配"，参数一变就删不掉 → 改**按包名整块删**（幂等）；
  3. 好结局门槛是"主线完成那一刻"锁定的（balance-lab 之后继续刷的成就不算）→ 定 5，完成时必达。
- **双向实测**（演示包 garden，验证后已移除）：生成 → 619/619 全绿 → 无头 4h12m 通关 2/2 层、
  好结局「明亮」可达 → `-Remove` 删净回 C1 绿态。**交付物是工具本身，不留演示包。**
