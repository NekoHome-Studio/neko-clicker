### B. ✅ 已修：`CHANGELOG.md` 那句"关停时强制存档一次"（原文保留，更正如下）

**当时的判断是对的，而且现在修掉了。** 原文（保留以便看出当时看到了什么）：

> 它说"关停时经 `ApplicationStopping` 强制存档一次"。实测**没有发生**：
> `StopAsync` 在排入存盘任务**之前**就 `_stopping.Cancel()`，ticker 循环直接退出、任务从未排空。
> 证据：对照宿主日志说 `Application is shutting down…`，而存档槽没被重写。
>
> **建议**：先**改文档说真话**（"关停不保证存档；请用「存档」按钮"），把 bug 单独记一条。
> 理由：修它会**改变正常行为**，而"关停该不该存"是产品决定——不该顺手替你定。

**实际做的**：没采纳"只改文档"那条建议——`Program.cs` 里那条注释与 1.2.0 的条目都把
"优雅关停存一次档"当成**预期行为**，所以按预期行为修，而不是按现状改文档。
修法：`StopAsync` 先排存盘任务、**等它自己的回执**（不绑 `_stopping`）再取消循环；
循环退出前补一次队列排空。

**证据**（`--save-root <临时目录>`）：显式存档后往槽位尾追加标记 → `CTRL_BREAK_EVENT`
→ 标记被整体重写、日志有 `[cafe] 退出前已存档：cafe.json`；**同一套探针**换硬杀
（`taskkill /F /T`）→ 标记原样留着、没有那句话。两次都在显式存档后 0.2 秒内结束，
且真实的 `saves/` 前后指纹一致（排除"写是别的进程干的"）。

**仍然成立的那半句**：调试门在 `StopAsync` 里的守卫**此前**是纯防御性的；修好之后
它的效果可观测了（调试会话退出时会明说"不写存档"）。

4. **#2 九命是矩阵里的"可选"，最终照做了**（`ROADMAP.md:606`：四条立场 + 六次表态，

其中 7 个是 `–`（#1/#4/#5/#6/#7/#8/#9）、1 个是"可选"（#2）、2 个是 ✅（#3/#10）——

（靠 R11 的定位解释，不靠矩阵）。
另：`engine/docs/CONTENT_AUTHORING.md` §13（第 695-744 行）只讲**怎么写**表态 / 立场 / 结局
（四条硬规则里唯一一条"必须"是"必须留一个兜底结局"），**没有一句关于"哪些包该有"的政策**——
所以"要不要给某个包加分支叙事"在那份手册里找不到依据，只能回设计矩阵看。

#### J 的落地实况（做什么、决定了什么、证据在哪）

- **公开成员只加了一个**：`GameEngine.MarkPendingChoicesShown()`（`engine/core/GameEngine.cs`）。
  引擎不猜视图层；宿主在**真的把待答表态渲染出来**时调用它。判定改成
  `待答 && 那批里至少一条没被展示过` → 推迟（`EndingSystem.Check`）。
  逐条记账，存在 `GameState.Counters`（键 `$choice_shown_<id>`）——
  **存档格式没动、存档版本号没升**，标记随存档往返。
- **30 秒的处置：删掉（不保留成兜底）。** 理由：本次的语义就是"被展示之前无论过多久都不落定"，
  任何定时兜底都会**违反**它（一到点就落定 ⇒ 把"玩家没看到"重新变成"玩家看到了"）。
  代价照上面那条：从未被展示过的存档没有收场。
  **公开成员为兼容保留**（删要按 §2 升 major，而这次是有意的 minor）：
  `EndingGraceSeconds` / `DefaultGraceSeconds` / `Grace()` / `GraceRemaining()`
  运行行为一行未改，但**判定不再读它们**；**设了 `EndingGraceSeconds` 会在构造时发一条
  Warning 通知**（"设置了却没有任何效果"不许沉默）。
- **跨会话（读档）算不算"展示过"？算。** 条件问的是"玩家有没有被展示过"，而玩家是跨会话的
  （它换掉的那条定时宽限同样随存档走）。未展示过的**不会**因为读档变成展示过——
  那条"修法"会让机制永远为真，而且测试全绿。
- **宿主的判据是"面板真的画出来了"，不是角标**：终端宿主由渲染器回答
  （`TerminalUi.ShowsChoicesPanel`，焦点/过小窗口/帮助浮层都算在内），且**写终端成功之后**才报告；
  Web 宿主在「表态」面板真的显示时发 `choicesShown` 命令（标签栏角标不算——只报条数不等于看到了选择）。
- **那条守卫用例的重写**：`GraceExpiresSoAnUnansweredChoiceCannotStallTheEndingForever`
  → `NotShownChoicesStallTheEndingForeverAndThatIsDeliberate`（旧名字留在文件注释与 CHANGELOG 里可 grep）。
  另外 4 个"跑到终局"的机器人用例补上了宿主该做的那一步（否则它们测的就不再是内容）。
  用例 **455 → 460**；三条故障注入证明了判别力（把定时兜底加回来 → 2 条红；
  让展示信号失效 → 5 条红，含三条内容层的兜底结局用例；让终端宿主的可见性判据退化 → 1 条红）。
- **已知的边角（1.5.0 接受）**：如果玩家**本来就停在**表态面板上，那批新表态出现的下一拍
  就算"已展示"，结局可能紧跟着落定——细看只有一两帧。这是"条件是'看过'而不是'看过并想了一会儿'"
  的直接后果；旧机制在这条路径上会给一段固定时间。**没有**为它加任何计时（那会把定时器请回来）。
